* 给代码加上中文的注释.在类名,字段名,属性名,方法名上面使用xml注释。
* 类声明上面的注释应该详细介绍,并且需要跟随当前功能及时更新注释内容.
* 注意xml注释应该在[..]的Attribute声明行的上方.
* 注意在枚举项上使用xml注释，在函数的原始逻辑代码中可以添加适当的行内注释（//）.
* 可以补充原有的注释内容，但是注意千万不要简化原有的注释内容.
* 类的私有成员也要添加注释.
* 检查代码的隐患错误,加上注释todo之类的的.但是不要改动原始代码.
* 给关键的计算思路补上行内注释（//）.
* 超过200行的类需要划分region(使用中文region)
* 测试和自动化验证相关类型统一使用 Test 命名；测试类使用 `*Tests`，批处理验证类使用 `*TestBatch`，不要在类型、文件名或公开 API 名称中使用 `Smoke`、`SmokeTest`、`SmokeBatch`。
* 【强制：禁止无逻辑字段透传】数据承载类、ScriptableObject、可序列化配置和报告 DTO 必须直接使用小写 public 字段表达数据；禁止写成“private 或 `[SerializeField]` 字段 + 仅返回该字段的 public 属性”。“优先”“建议”“保持封装”“未来可能扩展”和“API 风格统一”均不能作为保留透传属性的理由。
  * 禁止形式包括 `public T Name => _name;`、`public T Name { get { return _name; } }` 及语义等价写法。
  * 正确形式为 `public T name;`。如果是非序列化的运行时状态并且需要限制外部写入，应使用自动属性 `public T Name { get; private set; }`，不得再声明仅用于该属性的同义 backing field。
  * 只有属性确实承担计算、校验或规范化、懒加载或缓存、保护明确不变量，或者临时兼容既有公开 API 时才能保留。保留时必须能指出具体逻辑、不变量或兼容对象；只复制字段值不算封装。
  * 修改符合上述范围的类型时，必须检查并清理整个类型中已有的无逻辑透传属性，不能只让本次新增或直接涉及的字段合规。用户要求整理目录或模块时，必须递归扫描其中全部 C# 文件，并在完成结果中报告清理前后的无逻辑透传属性数量。
  * Unity 序列化字段从 private 改为 public 并发生改名时，必须使用 `[FormerlySerializedAs("_旧字段名")]` 保留现有资产数据，同时更新 `SerializedObject.FindProperty`、`FindPropertyRelative`、自定义 Inspector 或 Drawer 和全部调用方，最后执行 Unity 编译验证。
  * 本规则不要求把服务、控制器或运行时容器的内部可变状态暴露为 public 字段；这类状态应使用私有字段或带 private setter 的自动属性。计算属性、本地化属性、集合计数、校验结果和懒加载入口不属于无逻辑透传。
